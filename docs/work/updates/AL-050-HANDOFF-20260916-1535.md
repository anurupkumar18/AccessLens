AL-050 is handed to review and releases its claim. A security review of
AL-048/AL-049 (run this session) found that `services/live-session/src/rules.ts`
checked every other structured field's shape (`pointer`, `arState`) but not
`caption`'s -- it only checked the field *name* was known. Fixed by mirroring
four new rules (`caption-not-an-object`, `caption-text-missing`,
`caption-text-too-long`, `caption-isfinal-not-boolean`) in both
`reference_event_check.py` and `rules.ts`, in the same order, with a new
negative fixture and an end-to-end relay test proving the relay actually
rejects an oversized caption rather than broadcasting it. No shared contract
change was needed -- the client-side Zod/JSON Schema was already correct;
this closes the gap between "the client validates" and "the server, which
cannot trust the client, also validates."
