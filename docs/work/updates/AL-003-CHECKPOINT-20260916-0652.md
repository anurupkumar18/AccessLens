Independent second review of the AL-003 `capture.stopped` contract, requested by
`docs/DEMO_PROOF_SPRINT.md` as the gate before deployment. The reviewer is not
the implementing agent. This review reads code and runs local checks only; it
did not deploy, did not exercise a browser, and did not observe a human.

## Verdict against the four required statements

**1. Base-only and instructor-only; no raw media, asset, region, preference, or
identity field — QUALIFIED, not fully confirmed.**

Instructor-only is confirmed at every layer: `capture.stopped` is in
`INSTRUCTOR_ONLY_TYPES` in both `reference_event_check.py` and
`services/live-session/src/rules.ts`, so the relay refuses a student publisher
with `role-not-permitted-to-publish`.

No raw media, preference, or identity is confirmed and was verified by running
the reference validator directly: `frameData`, `studentId`, and `preferences`
each bounce as `field-not-on-contract:<name>` from the `KNOWN_FIELDS` allowlist.

Base-only with respect to **asset and region** holds only at the schema layer.
`LiveEventSchema` (strict discriminated union) and `live-event.schema.json`
(which sets `assetId`/`regionId`/`pointer`/`arState` to `false` for this type)
both forbid it. Neither `rules.ts` nor `reference_event_check.py` does. A
`capture.stopped` carrying a real `assetId` and `regionId` is **accepted** by the
relay today, while the same fields on `source.unmatched` are refused as
`unmatched-event-names-content:*`. The guard charter A9 earned for one base-only
type was not extended to the other. Recorded as T-31.

**2. Stop and browser source termination release local capture but retain the
temporary session and last trusted student state — CONFIRMED.**

`captureController.ts` routes both explicit `stop()` and the browser's own
`granted.onEnded(...)` through one `endSharing()`, which calls `releaseStream()`,
returns to `idle`, keeps `sessionId` non-null, and emits `capture.stopped`.
`relay.ts` deliberately does not close the session on this type and stores it in
`VIEW_BEARING` as the session's latest state. `liveState.ts` returns
`{...current, status: 'stopped'}`, preserving `assetId`, `regionId`, and
`hotspotId` rather than clearing them. Covered by `captureController.test.ts`
(the source-ended and stop paths) and `relay.test.ts:206`.

**3. A later `session.started` resumes the same session with a monotonic
sequence; only `session.ended` closes delivery — CONFIRMED.**

`start()` computes `openedHere = sessionId === null`, so a restart after stop
reuses the retained id and does not re-`create`. The `sequence` counter is not
reset by `endSharing()` or `resetRecognition()`, so numbering stays monotonic
across a stop/restart. On the relay, only `session.ended` reaches
`closeSession`, and both `join` and `resume` refuse a closed session with
`session-not-open`.

**4. The reviewed service has been rebuilt before CDK deployment — NOT
APPLICABLE YET.**

The build itself is green (`make check` runs esbuild to `dist/index.mjs`,
24.9 kb). No deployment was attempted. This box cannot be ticked by a review.

## Independent reproduction of the stale-endpoint finding

The previous session's critical result was re-verified rather than taken on
trust. A single disposable session was created against the existing endpoint and
closed immediately; it sent two events and carried no student, identity, or media
data:

```
create          -> {"kind":"capability", ... "role":"instructor"}
session.started -> {"kind":"accepted"}
capture.stopped -> {"kind":"rejected","rules":["event-type-not-allowlisted"]}
close           -> {"kind":"closed"}
```

The existing endpoint is confirmed stale for AL-003. Deployed stop-versus-end
behavior must not be claimed.

## Findings that should be resolved or explicitly accepted before deployment

- **T-31** — relay does not enforce base-only for `capture.stopped`, unlike
  `source.unmatched`. Not reachable from the shipped instructor controller,
  whose `Emittable` type is base-only, so this is client-trust hardening rather
  than a demo-blocking defect. `rules.ts`'s own docstring states the principle it
  misses here: "a client is whatever the person running it says it is."
- **T-32** — `Relay.resume()` and the `$connect` route that reaches it have no
  test anywhere, and the AL-004 bench's "rejoining student" check reconnects as a
  brand-new anonymous `join`. `WebSocketSessionClient` reconnects by presenting
  its stored capability on `$connect`, so the reconnect path the demo actually
  uses is the one neither the unit suite nor the bench covers.
- **T-33** — `liveRelayClient.subscribe` drops any event failing
  `LiveEventSchema.safeParse` with no else branch and no diagnostic.

T-31 and T-33 compose into the one failure mode AL-003 exists to prevent: an
accepted-but-non-conforming `capture.stopped` becomes the session's latest state,
conforming students silently discard it, and the student view stays "live" after
sharing stopped. That is the same cell AL-004's bench table marks "Not measured".

No code was changed by this review. `rules.ts` is Part 4 territory and
`reference_event_check.py` is Part 5's, so per `AGENTS.md` these are threads, not
edits from here.
